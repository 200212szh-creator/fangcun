# 方寸前端动效升级方案

> 状态：待实施  
> 适用项目：方寸 / Fangcun Archive  
> 技术栈：Next.js 15、React 19、Tailwind CSS  
> 目标气质：安静、克制、清晰、像整理一间私人藏书室

## 1. 背景与判断

当前界面已经具备基础动效：页面淡入、列表错峰出现、按钮按压、加载旋转、保存成功闪动，并支持 `prefers-reduced-motion`。问题不是缺少动画，而是多种场景复用同一种动画，导致动作缺乏语义：

- 页面、移动抽屉和列表都使用向上淡入，空间方向不清楚。
- 普通卡片普遍上浮并增加阴影，显得像通用后台模板，不符合档案工具的沉静气质。
- 搜索列表最多八项错峰出现，总完成时间偏长，连续检索时尤其拖沓。
- 成功光圈、按钮文字切换和骨架屏替换可能造成视觉跳动。
- 组件只有进入效果，关闭、返回、内容替换缺少对应的退出或交叉淡化。
- 时长与缓动散落在 CSS 和组件 class 中，尚未形成统一的动效语言。

## 2. 升级目标

1. 动画只解释状态变化、空间关系或操作结果，不承担装饰任务。
2. 每个视图最多突出 1–2 个关键动作，其余变化保持即时或轻微过渡。
3. 所有反馈在点击后 100ms 内开始，普通动效 150–300ms 内结束。
4. 页面导航不被动画阻塞；快速连续操作可以立即打断旧动画。
5. 只使用 `transform` 与 `opacity` 承担位移动画，避免动画引发布局重排。
6. 不增加 GSAP、Framer Motion 等运行时依赖；优先使用 CSS 与现有 React 状态。
7. 完整支持减少动态效果，关闭动画后内容、反馈和导航仍然可用。

## 3. 非目标

- 不重做品牌、颜色、字体或页面布局。
- 不为“更有感觉”增加视差、滚动劫持、字符拆分、弹跳或持续装饰动画。
- 不把动画等待时间当作加载遮罩，不延迟路由和数据请求。
- 不在本轮混入二维码内容、封面排版、导航顺序等其他功能修改。
- 不修改未被现有路由引用的旧组件，先确认真实引用关系。

## 4. 动效设计令牌

统一在全局样式中建立语义令牌，组件不得继续随意写 `duration-200`、`duration-300` 或不同的 cubic-bezier。

| 令牌 | 建议值 | 用途 |
|---|---:|---|
| `--motion-press` | 90ms | 点击、按压的即时反馈 |
| `--motion-fast` | 140ms | 退出、关闭、内容淡出 |
| `--motion-base` | 200ms | 标签、按钮状态、提示进入 |
| `--motion-slow` | 260ms | 页面内容、抽屉进入 |
| `--ease-standard` | `cubic-bezier(.2, 0, 0, 1)` | 状态切换 |
| `--ease-enter` | `cubic-bezier(.16, 1, .3, 1)` | 元素进入 |
| `--ease-exit` | `cubic-bezier(.4, 0, 1, 1)` | 元素退出 |

约束：

- 退出时长约为进入时长的 60%–70%。
- 位移距离以 2–8px 为主；抽屉除外。
- 列表错峰每项 20–30ms，只处理前 4 项，总揭示时间不超过 320ms。
- 不使用超过 400ms 的单次界面动画。
- 不使用 `transition: all`；只声明实际变化的属性。

## 5. 基础动效原语

建立少量可复用、语义明确的类或组件：

- `motion-page-in`：主内容透明度 0→1、Y 4px→0，260ms；仅在真正的路由内容首次挂载时使用。
- `motion-panel-in/out`：抽屉、浮层、菜单的进入与退出；方向由触发位置决定。
- `motion-feedback-in/out`：成功、失败和提示信息，透明度加 2px 位移。
- `motion-list-in`：首次加载列表时错峰，更新、筛选和重新渲染不重复播放。
- `motion-press`：按钮/可点击卡片在 90ms 内缩放至 0.99，释放后立即恢复；不得移动周边布局。
- `motion-crossfade`：同一容器中的加载、空状态、结果和错误状态进行 140–180ms 交叉淡化。

移除或替换当前用途过宽的 `page-enter`、`stagger-item`、`success-flash`。如果出于兼容暂时保留，必须把它们限定为上述语义原语的别名并逐步迁移。

## 6. 分区域改造

### 6.1 应用外壳与页面切换

- 侧栏、顶栏和移动底栏保持稳定，不随页面重新入场。
- 路由变化只让主内容区域轻微淡入，不为等待动画而阻塞导航。
- 返回操作与前进操作保持相同的快速节奏；当前架构无法可靠识别方向时，使用无方向的交叉淡化，不伪造左右滑动。
- 路由完成后焦点移到 `main`；减少动态效果下不播放位移。
- 侧栏当前项只过渡背景、文字与指示线，不整体上浮。

### 6.2 移动菜单

- 遮罩在 140ms 内淡入、100ms 内淡出。
- 抽屉从左侧进入：X -16px→0、透明度 0→1，220ms；关闭为 140ms。
- 关闭时先播放退出，再卸载；按 Escape、点击遮罩或选择导航项都可关闭。
- 打开后焦点进入菜单，关闭后返回触发按钮；动画不能锁住点击。

### 6.3 按钮、输入框与标签页

- 按钮按压缩放由 0.98 收敛到 0.99，90ms 内反馈。
- 加载状态保持按钮宽度和图标槽位稳定，避免“保存”变“保存中”时横向跳动。
- 成功结果使用对勾＋简短文字淡入，不再使用大范围光圈闪烁。
- 错误反馈不使用抖动；通过图标、文字和语义颜色说明原因及恢复方式。
- 标签页切换使用活动底色/指示器 160–200ms 过渡，内容 140ms 交叉淡化；键盘切换不延迟。
- 输入框焦点仅过渡边框、背景和焦点环，不缩放表单控件。

### 6.4 卡片、书封与列表

- 普通信息卡片取消统一 `translateY`；悬停只改变边框、底色或极轻阴影。
- 只有书封或书籍卡片可以保留“拿起一本书”的物理隐喻：最多上移 1–2px，150–180ms。
- 列表首次返回时仅前 4 项错峰 20–30ms；重新搜索、排序或切换过滤条件时采用整体交叉淡化。
- 50 项以上列表不逐项动画，避免主线程和滚动压力。
- 封面缺图、长书名和文本换行时不得因为动效改变卡片高度。

### 6.5 添加图书与统一检索

- 输入阶段不播放动画；300ms 内完成的请求不显示骨架屏，超过 300ms 才显示同步的轻量加载状态。
- 候选结果替换采用交叉淡化；快速连续输入取消旧请求，也要取消旧动画。
- 点击候选后，选中态在原位置完成边框/底色变化并出现对勾；版本区域出现时使用一次 4px 淡入。
- 自动滚动到版本区域必须尊重减少动态效果，并允许用户立即打断。
- 骨架屏使用同组统一的缓慢 shimmer；内容到达后立即停止，不与真实内容叠加闪烁。
- 保存过程保持表单和按钮尺寸稳定；成功提示不遮挡下一步操作。

### 6.6 图书详情、借阅与批注

- “展开完整档案”只旋转箭头并淡入内容，不动画计算高度，不产生页面弹跳。
- 借出、续借、归还通过同一容器交叉淡化状态，保留容器最小高度，避免表单突然塌陷。
- 保存批注后，新条目可以轻微淡入并短暂显示成功标记；删除时先确认，退出动画不得延迟实际删除请求。
- 任何状态变化都以文本/图标为主，颜色和动画只作为辅助。

### 6.7 分类、书架与二维位置视图

- 分类/书架/标签面板切换采用短交叉淡化，不整页重播。
- “更多操作”从触发按钮附近淡入/缩放，关闭更快；确保层级不被卡片裁切。
- 排序操作若仍使用按钮，位置变化可使用短暂 FLIP 式位移，但不引入动画库；无法稳定实现时宁可即时更新。
- 二维书架中的书仅在悬停/聚焦时上移 1px；定位到目标时使用一次低强度边框强调，不持续闪烁。

### 6.8 欢迎页

- 欢迎页只保留一次轻量入场：品牌文字与抽象书架最多两个层级。
- 抽象书籍不持续漂浮、不循环呼吸；首次出现后保持静止。
- “进入书库”按钮只提供按压和焦点反馈，不使用弹跳或无限提示。

## 7. 无障碍与减少动态效果

- 保留并完善 `prefers-reduced-motion: reduce`：关闭位移、错峰、平滑滚动和持续 shimmer。
- 减少动态效果下，加载必须仍有文字、静态进度图形或 `aria-live` 提示。
- 成功和错误提示使用 `aria-live="polite"` / `role="alert"`，动画不能成为唯一提示。
- 抽屉和菜单维持正确焦点顺序；退出动画期间不可让焦点落到背景。
- 页面切换、标签切换和列表动画不改变 DOM 阅读顺序。
- 所有触控目标保持至少 44×44px，动画不得缩小实际点击区域。

## 8. 性能边界

- 不新增动效运行时依赖，生产 JavaScript 不因本轮显著增加；若增加超过 20KB gzip，视为失败。
- 动画只使用 `transform`、`opacity`；背景、边框可做短状态过渡，但不做长时间阴影动画。
- 动画期间单帧脚本工作目标小于 16ms；不得出现由动效新增的明显长任务。
- CLS 保持小于 0.1；加载文字、图标和提示出现时不推动相邻布局。
- 页面导航、点击和输入的视觉反馈在 100ms 内开始。
- 关闭页面或卸载组件时清理计时器、动画帧和监听器。

## 9. 实施顺序

### A. 令牌与清理

1. 记录当前关键页面短视频或连续截图作为基线。
2. 建立动效令牌与基础原语。
3. 清点真实被路由引用的组件；排除旧的、重复的 `library-app.tsx` 等未使用实现。
4. 移除大范围通用上浮、重复淡入和成功光圈。

### B. 核心交互

1. 应用外壳、页面内容和移动抽屉。
2. Button、Tabs、Notice/反馈、加载状态。
3. 添加图书与统一检索的加载—结果—选中—保存链路。

### C. 内容区域

1. 书籍卡片、图书详情、完整档案展开。
2. 借阅与批注状态替换。
3. 分类/书架/标签和真实位置视图。
4. 欢迎页收敛动画。

### D. 定向验收与文档

1. 普通动态、减少动态效果、键盘和触控分别验收。
2. 仅修复有证据的问题，不继续添加装饰性动效。
3. 把最终令牌、语义和禁用项同步回设计系统文档。

## 10. 针对性测试方式

遵循风险驱动原则，不机械重复全站测试。

### 自动检查

- 全局 CSS、应用外壳和基础组件改变后，各运行一次 typecheck、lint、build。
- 编写一组动效定向 Playwright 用例，覆盖：
  - 移动抽屉打开、关闭、Escape、焦点返回。
  - 快速连续路由跳转不会卡住或留下遮罩。
  - 添加图书快速输入会取消旧请求和旧动画。
  - 保存按钮宽度稳定、不能重复提交，成功/失败可被辅助技术识别。
  - 标签切换与详情展开后内容立即可操作。
  - `prefers-reduced-motion: reduce` 时位移、错峰和平滑滚动被关闭。
  - 375px 与 1440px 下无横向溢出、无固定导航遮挡。
- 不触及数据库结构，不重复执行数据库迁移/恢复全套测试。
- 不触及书目算法，不重复跑与动效无关的深度数据测试。

### 人工视觉验收

- 尺寸：1440×778、390×844、375px 横竖屏。
- 页面：首页、添加图书、统一检索、图书详情、分类与位置、移动菜单。
- 状态：空、加载、结果、成功、失败、禁用、减少动态效果。
- 操作：快速连点、快速切换标签、请求未结束时返回、滚动中打开/关闭菜单。
- 对比实施前后短视频，确认动作更少、更快、方向更清楚，而不是仅“看起来更明显”。

## 11. 通过标准

1. 页面、抽屉、列表不再共享同一套无差别入场动作。
2. 每个页面可见的主动动画不超过两个重点，连续操作时不反复重播装饰动画。
3. 所有常规动效在 300ms 内结束，复杂动效不超过 400ms，总列表揭示不超过 320ms。
4. 移动抽屉具有正确进入/退出方向与焦点管理。
5. 普通卡片不再普遍上浮；书封的物理隐喻克制且一致。
6. 保存、搜索、借阅、批注状态切换没有按钮宽度跳动和明显布局抖动。
7. 快速操作可打断旧动画，不出现卡死、遮罩残留或不可点击状态。
8. 减少动态效果下功能完整，加载和结果仍有文字反馈。
9. 无新增横向溢出、CLS 或明显主线程卡顿；不新增大型动效依赖。
10. 定向测试通过，typecheck、lint、build 通过，正式数据库不写入测试数据。

## 12. 交付物

- 更新后的动效令牌和基础原语。
- 完成上述关键页面和组件改造。
- 动效定向 Playwright 测试。
- 桌面、移动、减少动态效果三组实施后证据。
- 更新设计系统中的动效章节。
- 一份简短报告：删除了哪些无效动画、保留了哪些语义动画、性能和可访问性结果、尚存限制。
