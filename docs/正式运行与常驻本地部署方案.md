# 方寸正式运行与常驻本地部署方案

> 状态：待实施  
> 目标平台：Windows 本机  
> 应用：方寸 / Fangcun Archive  
> 服务入口：http://localhost:3000  
> 核心原则：数据与程序分离、无命令窗口、可自动恢复、可验证、可回退

## 1. 当前状态与风险

当前项目可以通过 `next start -p 3000` 运行，但还不是可长期无人值守的本地应用：

- 旧的 `启动藏序.bat` 仍使用开发模式，并且会显示命令窗口。
- 正式服务由普通进程直接启动，没有开机自启、进程守护和健康检查。
- 数据库默认位于项目内 `data/library.db`，路径依赖当前工作目录。
- 数据库仍有 WAL/SHM 运行文件，迁移时必须先安全停服和 checkpoint，不能直接删除或随意复制。
- 现有备份脚本输出到项目内 `artifacts/db-backups`，没有每日一次、有效性校验和保留数量控制。
- 封面目前主要来自远程 URL，尚没有明确的本地封面固定存储约定。
- 存在测试数据库、测试结果、历史截图、旧备份目录、`.bak` 和旧启动器等候选清理项，但不能在引用关系与恢复能力确认前批量删除。

## 2. 完成后的用户体验

1. 登录 Windows 后，方寸在后台自动启动，不显示命令窗口。
2. 点击桌面“方寸”图标：
   - 服务已健康：立即打开浏览器。
   - 服务未启动：启动器在后台拉起服务，等待健康后再打开浏览器。
   - 启动失败：不打开错误网页，显示中文说明、日志位置和恢复入口。
3. Node/Next 进程异常退出会自动重启；服务无响应连续达到阈值后会被安全重启。
4. 数据库、封面、配置、日志和备份都有固定目录；更新代码、重建 `.next`、切换发行版本和重启电脑不会影响真实藏书。
5. 每天首次启动前创建一份经过校验的数据库备份，默认保留最近 21 份。
6. 数据库完整性异常时停止正式启动，提示用户选择恢复，不静默覆盖损坏库。
7. 日志自动按大小和日期轮换，旧日志自动清理，不会无限占用磁盘。

## 3. 固定目录结构

程序源码继续位于：

```text
D:\图书库
```

所有用户数据迁移到源码目录之外：

```text
D:\方寸数据\
├─ data\
│  ├─ library.db
│  ├─ library.db-wal
│  └─ library.db-shm
├─ covers\
├─ backups\
│  ├─ daily\
│  ├─ pre-upgrade\
│  └─ media\
├─ config\
│  └─ service.env
├─ logs\
│  ├─ service\
│  ├─ watchdog\
│  └─ launcher\
├─ state\
│  ├─ service.pid
│  ├─ current-release.txt
│  ├─ last-daily-backup.txt
│  └─ health-status.json
├─ recovery\
└─ quarantine\
```

要求：

- 通过 `FANGCUN_DATA_DIR` 与绝对 `DATABASE_URL` 指向固定目录，不再依赖 `process.cwd()`。
- 配置文件不写入密钥日志，限制为当前 Windows 用户可读。
- 封面文件使用稳定 ID 或内容哈希命名，通过应用 API 提供，不放入 `.next` 或临时目录。
- 发行构建可以删除和替换，`D:\方寸数据` 不参与构建清理。
- 启动和清理脚本禁止把环境变量名设置为 `HOME`、`home` 或 `CODEX_HOME`。

## 4. 正式发行结构

在 `next.config.ts` 启用 Next.js standalone 输出。每次构建生成独立发行目录：

```text
D:\图书库\runtime\
├─ releases\
│  ├─ 2026-09-08_1400\
│  └─ 2026-09-09_0930\
├─ launcher\
├─ current-release.txt
└─ recovery-ui\
```

发行策略：

- 构建永远先进入新的 release 目录，不覆盖正在运行的版本。
- release 必须包含 standalone server、`.next/static`、必要的 `public` 资源和构建编号。
- 构建完成后先使用临时端口和复制数据库验证。
- 通过验证后才停止旧服务，原子更新 `current-release.txt` 并启动新版本。
- 新版本健康检查失败时自动切回上一版本；真实数据库不随发行版本切换。
- 默认保留最近 2 个可运行发行版本，其余已确认无用的旧发行可以清理。
- 日常运行使用 `NODE_ENV=production`，不再使用 `next dev`。

## 5. 健康检查

新增只读 `/api/health`：

```json
{
  "app": "fangcun-archive",
  "status": "ok",
  "database": "ok",
  "buildId": "...",
  "time": "..."
}
```

健康检查要求：

- 不返回书名、作者、借阅人、文件路径、密钥等隐私内容。
- 校验应用签名、构建版本、数据库可连接和必要表存在。
- 普通探测只执行轻量查询；完整 `PRAGMA integrity_check` 仅在每日首次启动、备份和恢复流程执行。
- 端口 3000 已被占用时，先检查健康签名：
  - 是方寸且健康：复用，不重复启动。
  - 是未知程序：绝不强行结束，显示端口冲突并记录日志。

## 6. 后台守护

使用 Windows 自带的任务计划程序和隐藏 PowerShell/WSH 启动方式，第一版不引入 NSSM、PM2 或来源不明的服务包装器。

### 6.1 开机任务

- 任务名：`Fangcun Archive Service`
- 触发：当前用户登录后延迟约 20 秒。
- 界面：隐藏运行，不显示终端窗口。
- 重复实例策略：已有守护程序运行时忽略新实例。
- 守护程序自身异常退出：任务计划程序 1 分钟后重启。
- 允许使用电池，不要求网络连接。
- 第一版只监听 `127.0.0.1:3000`，不开放公网或局域网防火墙。

### 6.2 守护逻辑

- 守护程序只管理由自己启动、路径和 PID 都可验证的方寸进程。
- 子进程退出：按 2 秒、5 秒、15 秒、30 秒、最长 5 分钟退避重启。
- 每 30 秒请求一次健康接口，单次超时 3 秒。
- 连续 3 次健康失败才重启，避免因一次短暂卡顿误杀服务。
- 每小时重启达到上限后停止重启风暴，写入故障状态并显示中文通知。
- 停止服务时优先正常结束；需要结束进程树时，只处理已记录且路径匹配的 PID，绝不按端口批量结束未知进程。
- 所有后台 `Start-Process` 使用隐藏窗口。

## 7. 点击启动器与桌面图标

创建新的“方寸”桌面和开始菜单快捷方式，替代并删除旧的 `启动藏序.bat`。

启动器流程：

1. 请求 `/api/health`，确认是否为方寸服务。
2. 健康时直接打开 `http://localhost:3000/`。
3. 未运行时启动或唤醒 `Fangcun Archive Service` 计划任务。
4. 在后台轮询健康状态，最长等待 60 秒。
5. 只有收到正确应用签名和 HTTP 200 后才打开浏览器。
6. 等待期间不弹出终端，可显示小型中文启动提示。
7. 超时后不打开“无法访问”页面，而是显示：
   - 启动失败原因摘要
   - “重试”
   - “打开日志目录”
   - “打开恢复工具”

并发点击快捷方式必须合并为同一次启动，不产生多个服务进程或多个浏览器标签。

## 8. 每日备份、完整性与恢复

### 8.1 启动顺序

每天首次正式启动严格按以下顺序：

1. 获取单实例锁。
2. 定位固定数据库和当前发行版本。
3. 检查数据库是否存在；首次安装才允许创建空库。
4. 对已有数据库执行完整性检查和必要表校验。
5. 数据库有效时创建原子备份到临时文件。
6. 对备份再次执行完整性检查与关键记录数核对。
7. 校验通过后把临时文件改名为当天正式备份，并更新日期标记。
8. 清理超出保留规则的旧备份。
9. 启动正式服务。

### 8.2 备份规则

- 每个本地自然日首次启动创建一次，默认保留最近 21 份有效日备份。
- 同一天重复启动不重复创建，用户手动“立即备份”除外。
- 文件名包含日期与校验结果，不仅依赖修改时间。
- 优先使用 SQLite 在线备份能力或在停服状态下安全 checkpoint 后复制；不复制一个仍在写入且未处理 WAL 的数据库。
- 每次升级前额外创建 `pre-upgrade` 备份，不计入 21 份日备份。
- 清理时至少保留最近 3 份有效备份和最新升级前备份；唯一可恢复副本绝不删除。
- 本地封面使用内容哈希存储并生成清单；每日数据库备份保留封面引用，新增封面同步到 `backups/media`，不重复复制相同内容。

### 8.3 异常处理

若正式数据库完整性检查失败：

- 不启动正式服务。
- 不生成“正常日备份”，也不覆盖任何已有备份。
- 将损坏数据库按时间复制到 `recovery`，明确标记为损坏副本。
- 显示恢复提示，列出最近有效备份的日期、大小和基本记录数。
- 用户必须明确选择备份后才执行恢复。
- 恢复先写入新临时文件，校验通过后再切换；原损坏文件继续保留。
- 恢复结束后重新核对版本、藏书、书架、借阅和批注数量。

## 9. 日志轮换

- 服务、守护和启动器分开记录，避免单个文件无限增长。
- 单日志文件上限 5MB，达到上限后轮换。
- 默认保留最近 14 天且总量不超过 100MB；超过时先删除最旧、已关闭的日志。
- 日志不记录 API 密钥、完整借阅联系方式、批注正文或数据库内容。
- 启动、重启、备份、恢复、版本切换和清理操作必须记录时间与结果。
- 正在写入的日志不得直接删除；轮换通过关闭文件句柄和原子改名完成。

## 10. 分阶段实施与实际实验

### R0｜只读盘点和安全基线

- 记录当前 3000 服务 PID、命令、版本和主要页面状态。
- 对正式数据库执行 checkpoint、完整性检查、文件哈希和关键记录数统计。
- 创建一份迁移前备份，校验可以在临时路径恢复。
- 输出保留/迁移/待清理清单，不修改真实数据。

通过标准：当前藏书、版本、书架、借阅、批注数量有可核对记录；迁移前备份可恢复。

### R1｜固定数据目录迁移

- 停止当前方寸服务。
- 将数据库和相关配置复制到 `D:\方寸数据`，不立即删除原文件。
- 处理 WAL/SHM，更新数据库绝对路径和封面目录配置。
- 使用临时端口从新数据目录启动并进行读写—重启—再读取验证。
- 对比迁移前后文件哈希、记录数与关键关联。

通过标准：新目录数据完整，应用重启后仍读取同一真实数据库；旧数据库保留为只读迁移保险。

### R2｜standalone 正式发行

- 新建发行目录并构建生产版本。
- 以复制数据库和临时端口验证首页、添加、书库、详情、管理、备份入口和健康接口。
- 验证更新/重建不会改变 `D:\方寸数据`。
- 失败时继续使用旧服务，不切换正式入口。

通过标准：生产版本独立启动，所有核心页面 200，构建目录删除后数据仍完整。

### R3｜后台守护和故障实验

在隔离服务上进行：

- 正常启动、停止和重复启动。
- 主动结束子进程，确认自动重启。
- 模拟连续健康失败，确认达到 3 次才重启。
- 连续失败触发退避，确认不会无限重启。
- 用其他临时服务占用端口，确认不会结束未知进程。
- 守护程序重启后仍能找到并管理正确的方寸服务。

通过标准：无终端窗口、无多实例、无误杀未知进程，故障和恢复均有日志。

### R4｜桌面启动器

- 创建带方寸图标的桌面和开始菜单入口。
- 分别验证服务健康、服务未启动、启动缓慢、端口冲突和启动失败。
- 服务未健康前浏览器不得打开。
- 快速连点图标不创建多个服务和重复标签。

通过标准：用户只需点击图标；成功时进入方寸，失败时看到中文恢复提示而非浏览器错误页。

### R5｜备份、保留和恢复演练

只使用复制数据库和模拟日期：

- 首次启动创建备份，同日重启不重复创建。
- 模拟 25 天，最终只保留 21 份有效日备份。
- 模拟无效备份、磁盘空间不足和备份中断，正式库不得受损。
- 对复制数据库制造损坏，确认程序停止启动、保留损坏副本并提示恢复。
- 选择有效备份恢复，核对所有关键记录与关联。

通过标准：无静默覆盖、无无效备份冒充成功、恢复结果可验证。

### R6｜安全清理

先生成清理清单，逐项记录绝对路径、大小、原因、是否可重建、是否被引用。清理分三类：

**可以在验证后直接删除的可重建临时项：**

- `data/e2e-library.db*` 等隔离测试数据库与 WAL/SHM。
- `test-results`、Playwright 临时报告和已经汇总完成的临时测试输出。
- 已停止隔离服务遗留的临时数据库、临时端口状态文件和临时日志。
- 不再被任何发行使用的旧 `.next` 构建缓存与超出保留规则的旧 release。
- 旧品牌开发启动器 `启动藏序.bat`，前提是新桌面启动器已经通过。

**必须先验证引用再处理的候选项：**

- `components/providers.bak`、旧的重复组件或 replacement 文件。
- 历史截图、motion/phase7 audit 证据和人工代码备份。
- `assets/fonts-source`：若构建仍引用则保留；若不再引用，只保留许可证与当前发行必需资源。
- 旧备份目录：先迁移最新有效备份到固定目录，再按保留策略清理。
- 临时方案文档：把有效内容合并进“运行维护说明”和设计系统后再删除。

**永远不得作为无用数据删除：**

- 当前正式数据库、WAL/SHM、固定封面、用户导入文件。
- 最近 21 份有效日备份、最新升级前备份和唯一可恢复副本。
- migrations、当前源代码、依赖许可证、使用说明、运行维护说明和仍被测试/构建引用的文件。
- 用户真实藏书、书架、借阅、批注、标签和论文数据。

对不确定文件先移动到 `D:\方寸数据\quarantine\<日期>`，完成正式运行与重启验收后再按清单永久删除。任何递归移动/删除前必须解析并核验绝对路径只位于明确的项目临时目录、旧发行目录或 quarantine；禁止对工作区根目录、用户目录、磁盘根目录使用递归删除。

通过标准：正式服务与构建仍通过，真实数据不变，清理清单中的每一项都有理由和恢复说明；最终只保留必要文档和有效数据。

### R7｜正式切换和重启验收

- 创建最终切换前备份。
- 把 3000 切换到新 standalone 发行和固定数据目录。
- 安装/启用开机任务与桌面快捷方式。
- 完成“停止服务→点击图标→自动启动→打开页面”实测。
- 验证异常退出后的自动恢复。
- 实际重启 Windows 会中断用户其他工作，只在再次获得用户明确许可后执行；未获许可时以任务计划程序手动触发和登录流程模拟作为预验收。

通过标准：重启或等价模拟后服务自动恢复，桌面图标可靠打开，数据、封面和备份计数保持一致。

## 11. 针对性测试策略

不机械重复既有功能全量测试：

- 修改数据库路径：只做迁移、完整性、读写重启和记录关联测试。
- 修改发行方式：运行 typecheck、lint、build 和核心页面烟雾测试。
- 修改守护/启动器：运行进程退出、无响应、端口冲突、多实例和等待打开测试。
- 修改备份恢复：全部使用复制数据库，执行日期保留、损坏、磁盘错误、原子切换和恢复核对。
- 清理后：检查引用、生产构建、3000 核心页面和正式数据只读计数。
- 最终只做一次综合验收，不在每个小改动后重复完整 E2E。

核心功能烟雾路径：欢迎页、首页、添加图书、藏书列表、一本书详情、分类与位置、设置/备份、健康接口。

## 12. 总体验收标准

1. Windows 登录后方寸后台自动启动，全程不显示命令窗口。
2. 服务退出或连续无响应后可以自动恢复，且不会发生重启风暴。
3. 点击桌面图标时，浏览器只在服务健康后打开。
4. 端口被未知程序占用时不会误杀进程，用户得到清晰提示。
5. 数据库、封面、配置、日志和备份全部位于固定目录；删除 `.next` 或创建新 release 不影响真实数据。
6. 每日首次启动备份有效，保留数量为 21；同日不重复，恢复流程不静默覆盖。
7. 数据库损坏时停止启动并提示恢复，损坏原件与有效备份都得到保留。
8. 日志按大小/日期轮换，总量受限且不包含敏感内容。
9. 清理后没有隔离测试数据库、临时报告、旧开发启动器和确认无引用的备份残留；真实数据与必要文档完整。
10. 最新正式构建通过，localhost:3000 和核心页面可用，正式数据计数与切换前一致。

## 14. 实施报告要求

每完成一个阶段记录：

- 做了什么、使用了哪一个数据副本。
- 实际执行的针对性实验及结果。
- 正式数据库与封面的前后计数/校验结果。
- 生成或删除的文件清单。
- 当前服务 PID、发行编号和健康状态。
- 失败回退点和仍需用户确认的事项。

R0–R6 达标后自动继续。R7 中涉及真实 Windows 重启的步骤必须先请求用户确认；其他安全、可回退的本地实施可自主推进。
